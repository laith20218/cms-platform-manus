# أمن الاختبارات

## الإدارة

تستخدم مسارات الإدارة سياسات صريحة لمورد الاختبارات، مع ربط أفعال النشر والأرشفة وإدارة الأسئلة وقراءة النتائج بالأفعال العامة المخزنة حالياً عند الحاجة للتوافق. بعد فحص RBAC، يُحل مسار الاختبار إلى مادة الاختبار ثم يُطبق ABAC على نطاق الجامعة أو الكلية أو السنة أو المادة. لا تكفي صلاحية المورد وحدها.

## الطالب

تتطلب مسارات الطالب مصادقة واستحقاقاً صالحاً للمادة. تُقرأ الجلسة بشرط `StudentId` الحالي، ولذلك لا يمكن استخدام معرّف جلسة طالب آخر لقراءة النتيجة أو حفظ إجابة أو مراجعة المحاولة. لا تُقبل درجة أو حالة أو وقت انتهاء أو عدد محاولات من العميل.

## التزامن والتكرار

مفتاح idempotency لبدء الجلسة، وفهرس فريد للجلسة النشطة لكل طالب واختبار، وفهارس فريدة للإجابة والقطة، ومعالجة تعارض قاعدة البيانات تمنع الجلسات المكررة والإجابات المكررة. `AnalyticsRecordedAt` يمنع تكرار تأثير النتيجة في إحصاءات الطالب والأسئلة عند إعادة التسليم أو الاستعلام المتكرر.

## الإفصاح

لا تُرسل الإجابة الصحيحة أو التفسير إلا وفق اللقطة وسياسات الاختبار. `AllowReview` يحدد إمكانية المراجعة، بينما `ShowCorrectAnswers` و`ShowExplanations` يحددان الحقول المكشوفة بصورة مستقلة. Essay غير مدعوم في الاختبارات ذات التصحيح التلقائي حتى لا يحدث تصحيح غير موثوق.

## التدقيق

تُرسل عمليات البدء والحفظ والإلغاء والتسليم وانتهاء الوقت والإدارة إلى كاتب التدقيق الحالي، دون إدراج سلسلة اتصال أو بيانات اعتماد أو نص إجابة حساس في الرسالة. تُراجع مسارات الأخطاء كذلك لأنها قد تكشف معرّفات أو بيانات لا يحتاجها الطالب.
