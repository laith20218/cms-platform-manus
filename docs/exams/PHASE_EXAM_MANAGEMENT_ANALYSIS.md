# تحليل مرحلة إدارة الاختبارات

**تاريخ التحليل:** 28 أغسطس 2026
**حالة المرحلة عند البداية:** `NOT STARTED`
**قاعدة القرار:** الكود الجاري في المستودع هو المرجع التنفيذي، والمرفق `pasted_content_2.txt` هو مواصفة هذه المرحلة. وثائق المشروع الأقدم مرجع سياقي فقط عند التعارض.

## 1. خلاصة تنفيذية

يوجد في المشروع نموذج أولي صالح لإعادة الاستخدام: كيان `Exam`، و`ExamSession`، و`AttemptLog`، ومسارات طالب للبدء والتسليم والنتيجة والمراجعة، إضافة إلى إنشاء/تعديل/نشر/أرشفة محدودين للمدير. لكن هذا النموذج لا يحقق دورة الاختبار المطلوبة. فهو يحتفظ بالإجابات في ذاكرة React حتى التسليم، ويحسب المؤقت من ساعة العميل، ولا يحفظ ترتيب الأسئلة داخل المحاولة، ولا يطبق نافذة الإتاحة أو حد المحاولات أو إعادة المحاولة أو إلغاء آمن، ولا يملك واجهة إدارة للاختبارات أو نتائج إدارية أو ضمانات قاعدة بيانات لمنع المحاولات المتزامنة.

> **قرار التحليل:** يعاد استخدام الكيانات والمسارات الحالية حيث تكون صحيحة، مع توسعتها عبر علاقات صريحة للاختبار والأسئلة ولقطة ثابتة للمحاولة. لا تُنشأ بنية اختبار موازية أو جداول نتائج مكررة.

| البعد | الموجود فعلياً | الفجوة الرئيسية |
|---|---|---|
| دورة الاختبار | مسودة/نشر/أرشفة أساسية وجلسة مكتملة فقط | لا توجد قواعد نشر كاملة أو إتاحة أو حد محاولات أو إلغاء/انتهاء وقت مطابقان للمواصفة |
| الأسئلة | علاقة قديمة `Question.ExamId` وقائمة أسئلة عبر navigation | لا توجد علاقة many-to-many مرتبة ولا اختيار/إزالة/استبدال أو ترتيب محفوظ |
| المحاولة | `ExamSession` و`AttemptLog` | لا توجد لقطة للأسئلة ولا حفظ إجابة خادمي ولا idempotency ولا قيد محاولات فعالة |
| تجربة الطالب | صفحة مؤقت وخريطة أسئلة وتسليم كلي | لا استئناف موثوق ولا وقت خادمي ولا حفظ فوري ولا سياسة مراجعة مستقلة |
| الإدارة | CRUD محدود داخل `ExamsController` | لا قائمة أو wizard أو اختيار أسئلة أو نتائج أو صلاحيات إجراءات مفصلة |
| الأمن | JWT واستحقاق موقّع وفحص ملكية session | لا اختبارات صريحة للتزامن وIDOR/BOLA أو فرض كامل للنطاق الإداري |
| البيانات | EF Core وترحيلات موجودة | لا فهارس أو قيود لسياق المحاولة أو الإجابة أو النسخة التاريخية |

## 2. ما يوجد حالياً في الكود

### 2.1 الكيانات والعلاقات القابلة لإعادة الاستخدام

| المكوّن | الاستخدام الحالي | قرار إعادة الاستخدام |
|---|---|---|
| `Exam` | عنوان، مادة، مدة، درجة نجاح، ترتيب عشوائي، إظهار نتيجة، مراجعة، وحالة محتوى | يبقى الكيان المحوري ويُوسّع بإعدادات الإتاحة والمراجعة والنطاق الأكاديمي |
| `Question` | سؤال بنك مرتبط بمادة ومحاضرة وخيارات وشرح وحالة نشر | يبقى المصدر التحريري؛ لا تُنسخ الأسئلة عند التحرير، بل تُؤخذ لقطة عند بدء المحاولة |
| `ExamSession` | طالب، اختبار، وقت بدء/إنهاء، نتيجة، حالة، أول محاولة | يبقى سجل المحاولة ويُوسّع بحالة صريحة ووقت انتهاء وإعدادات مجمّدة وidempotency |
| `AttemptLog` | إجابة سؤال، صحة، زمن، رقم محاولة، وربط اختياري بجلسة | يبقى سجل إجابة المحاولة بعد إضافة قيد فريد لكل جلسة/سؤال وتحديث ذري |
| `IEntitlementService` و`ISignedEntitlementService` | وصول الطالب إلى محتوى المادة عبر الاشتراك | يبقيان بوابة الاستحقاق في القائمة والبدء والاستئناف والتسليم والنتيجة والمراجعة |
| `IPermissionService` | تحقق فعل/مورد ونطاق إداري | يبقى المرجع لصلاحيات الاختبارات ولا يعتمد على الدور وحده |

### 2.2 واجهات API الحالية

| المسار الحالي | حالة التنفيذ | حدود الواقع الحالي |
|---|---|---|
| `GET /api/v1/exams/by-subject/{subjectId}` | موجود للطالب | يعرض كل الاختبارات المنشورة بلا نافذة إتاحة أو معلومات قابلية البدء/الإعادة |
| `GET /api/v1/exams/{id}` | موجود للطالب | يتحقق من النشر والاستحقاق فقط |
| `POST /api/v1/exams/{id}/start` | موجود | يعيد أو ينشئ جلسة، لكنه بلا قيد فريد ولا حد محاولات أو وقت خادمي محفوظ |
| `POST /api/v1/exams/sessions/{id}/submit` | موجود | يستلم كل الإجابات مرة واحدة ويحسب النتيجة بلا لقطة أو idempotency |
| `GET /api/v1/exams/sessions/{id}/results` | موجود | يدعم المكتملة فقط ولا يميز timeout أو سياسة إظهار النتائج |
| `GET /api/v1/exams/sessions/{id}/review` | موجود | يتحكم به `AllowReview` فقط ويكشف الإجابة والشرح معاً |
| `POST/PUT/.../publish/archive/delete` | موجود للمدير | لا توجد قائمة/تعديل نطاق/إدارة أسئلة/نتائج إدارية، والصلاحية تستخدم أفعالاً عامة |

### 2.3 الواجهة الحالية

واجهة الطالب تبدأ الاختبار تلقائياً عند فتح الصفحة، وتحتفظ بالإجابات ووقت السؤال في الذاكرة المحلية، وتبدأ مؤقتاً من `durationMinutes` ولا تعتمد على `expiresAt`. لذلك فإن refresh أو إغلاق التبويب يفقد الحالة قبل التسليم، وقد لا يمثل الوقت المتبقي الحقيقي. واجهة المراجعة قائمة خيارات تقليدية ولا تدعم سياسة منفصلة لكشف الإجابة الصحيحة والشرح أو أنواع السؤال الموسعة. لوحة الإدارة لا تحتوي حالياً على مركز اختبارات.

## 4. تصميم النطاق المقترح

### 4.1 نموذج الاختبار والإدارة

يضاف للاختبار نطاق محاضرات اختياري عبر علاقة قابلة للتوسعة، مع بيانات أساسية، وحالة `Draft` أو `Published` أو `Archived`، وترتيب عرض، ونافذة إتاحة اختيارية، وحد محاولات اختياري، ودرجة نجاح، وسياسات مستقلة لـ `AllowReview` و`ShowCorrectAnswers` و`ShowExplanations`. يجب أن تمنع عملية النشر خادمياً العنوان غير الصالح، أو المادة غير المتاحة، أو انعدام الأسئلة، أو سؤال غير منشور/محذوف/خارج المادة أو النطاق، أو مدة أو درجة أو نافذة أو حد محاولات غير منطقي.

تكون علاقة `ExamQuestion` هي المصدر المعتمد للأسئلة داخل اختبار محدد. تحتوي على `ExamId` و`QuestionId` و`SortOrder` وتُفرض فرادتها في قاعدة البيانات. تتولى أوامر الإضافة والإزالة وإعادة الترتيب والتحقق من أن السؤال منشور ومسموح للمسؤول وفي المادة ذاتها. ولا تعتمد الشاشة على ترتيب المتصفح فقط.

### 4.2 نموذج المحاولة والسجل التاريخي

عند البدء، ينشئ الخادم أو يعيد جلسة فعالة واحدة ضمن معاملة. ويُنشئ صفاً لكل سؤال في `ExamSessionQuestion` يتضمن ترتيب المحاولة ولقطة نص السؤال والخيارات والإجابة الصحيحة والشرح والوسوم. هذا يحافظ على صحة النتيجة والمراجعة التاريخيتين إذا عدّل المسؤول بنك الأسئلة لاحقاً. لا يرسل العميل الدرجة أو الوقت المتبقي أو المعرفات الموثوقة.

يستمر `AttemptLog` كسجل الإجابة المرتبط بالمحاولة، مع upsert ذري لكل زوج `ExamSessionId + QuestionId`. ويسجل النص التحريري أو خيار الإجابة وفق نوع السؤال. تُعد الإجابة الصحيحة في الاختبارات الموضوعية خادمياً فقط؛ السؤال التحريري يُخزن ويعرض إجابته النموذجية بحسب سياسة الاختبار، ولا يمنح درجة آلية موثوقة إلى أن يضاف تصحيح بشري صريح في مرحلة لاحقة. لا تخلط هذه المرحلة بين «ظهور الإجابة النموذجية» و«تصحيح تحريري آلي غير قابل للتدقيق».

### 4.3 حالات المحاولة والتزامن

تُعتمد الحالات `InProgress` و`Completed` و`TimedOut` و`Cancelled`. لا يكون `Cancelled` متاحاً إلا قبل حفظ أي إجابة، ولذلك لا يمكن استخدامه للتحايل على الحد. تستخدم البداية قيد PostgreSQL جزئياً يمنع أكثر من جلسة `InProgress` لنفس الطالب والاختبار، وتعيد الجلسة القائمة عند ضغط start المتكرر. يستخدم التسليم عملية انتقال حالة ذرية؛ إذا وصل طلب تسليم مكرر بعد الإكمال يعود نفس الناتج المحفوظ بدلاً من احتساب ثانٍ. ويحسب الخادم انتهاء الوقت من `ExpiresAt` وحالة المحاولة، لا من عدّاد الجهاز.

### 4.4 الاستحقاق، النطاق، التدقيق والإحصاءات

كل مسار طالب يثبت هوية الطالب وملكية المحاولة والاستحقاق الموقّع للمادة. وكل مسار إدارة يثبت `Resource=Exams` والفعل المناسب ثم نطاق المورد الفعلي. تنشأ أحداث تدقيق آمنة لإنشاء الاختبار وتعديله ونشره وأرشفته وحذفِه وتغيير أسئلته وبدء المحاولة وإكمالها وانتهاء وقتها. تُستخدم نتيجة `IsFirstAttempt` فقط في الإحصاءات والترتيب الرسميين، من دون منع المحاولات اللاحقة المشروعة أو تعديل نتيجة تاريخية.

### 4.5 أثر Offline

لا يعتمد الاختبار online على حالة مؤقت المتصفح أو حزم Offline الحالية. يجب أن تبقى الحزمة غير المتصلة، إن كانت مفعلة مستقبلاً، مرتبطة بلقطة اختبار مُوقّعة ومعرف محاولة ولا تنشئ نتائج متعارضة عند المزامنة. هذه الدفعة لا تدّعي تمكين اختبار محمي offline قبل إضافة عقد مزامنة وصلاحية منفصلين.

## 5. أثر قاعدة البيانات والترحيلات

يتطلب هذا التصميم ترحيلاً واحداً موجهاً من EF Core، ولا يستخدم SQL يدوي في الإنتاج. يشمل الترحيل جدول ربط الأسئلة، وجدول لقطة أسئلة المحاولة، وحقول الاختبار والجلسة اللازمة، وقيداً جزئياً لمحاولة فعالة، وقيداً فريداً لإجابة السؤال داخل الجلسة، وفهارس للبحث حسب الاختبار والطالب والحالة والانتهاء. تُختبر الترحيلات أولاً على فرع Neon مؤقت، ثم تُطبق في الإنتاج فقط مع نشر الخلفية المتوافق معها.

| الحاجة | آلية الحماية |
|---|---|
| منع جلستين فعالتين | فهرس فريد جزئي `student_id + exam_id` للحالة `InProgress` |
| منع جواب مكرر | فهرس فريد `exam_session_id + question_id` في سجل الإجابة |
| ترتيب ثابت | `ExamQuestion.SortOrder` و`ExamSessionQuestion.SortOrder` مفهرسان |
| عدم تغيير التاريخ | لقطة JSON أو حقول ثابتة للسؤال والسياسات في صفوف المحاولة |
| نافذة ووقت خادميان | `AvailableFrom/Until` و`ExpiresAt` UTC، وتحقق خادمي عند كل انتقال حساس |

## 6. أثر الواجهات

تضاف إلى لوحة الإدارة صفحة مركز اختبارات مرتبطة بالـ API الحقيقي، تشمل قائمة مُرقمة وبحثاً وفلترة، ومحرر مراحل: بيانات أساسية، نطاق أكاديمي، اختيار أسئلة، ترتيبها، قواعد الاختبار، مراجعة ونشر. تظهر الإجراءات فقط ضمن الصلاحية، لكن الخادم يبقى الحكم النهائي.

وتتحول صفحة الطالب إلى عميل محاولة خادمي: بدء صريح، استئناف جلسة قائمة، عرض الوقت المتبقي من الخادم، حفظ الإجابة بالتبديل أو التأكيد، إظهار حالة الاتصال، انتقال صحيح عند timeout، نتيجة تحتوي الصحيح والخاطئ وغير المجاب والزمن، ومراجعة تحترم سياسات الاختبار. لا تستخدم الواجهة mock data أو نتيجة محلية.

## 7. المخاطر وخطة خفضها

| الخطر | الخفض |
|---|---|
| تكرار محاولات أو نتائج عند ضغط/تبويب متزامن | معاملة وقيد فريد جزئي واختبارات concurrency ونتيجة idempotent للتسليم |
| كشف حلول أو شرح قبل السياسة المسموحة | DTO منفصل للطالب قبل التسليم ولقطة مراجعة لا تكشف إلا حقول السياسة |
| تلف البيانات التاريخية بعد تعديل بنك الأسئلة | لقطة سؤال وسياسات عند البدء؛ لا تعاد حساب نتيجة مكتملة من بنك حي |
| تجاوز IDOR/BOLA | تحقق ملكية session وexam وسؤال على الخادم واختبارات طالب/مدير خارج نطاقه |
| تعطيل خدمة حية بسبب ترحيل | تجربة ترحيل كاملة على فرع Neon وعكس واضح ونسخة احتياطية من schema قبل الإنتاج |
| تفاوت وثائق المشروع القديمة | تحديث وثائق الحقيقة والعقود ومصفوفة الواقع في نهاية المرحلة |
