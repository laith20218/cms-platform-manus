## 3. خارطة Wave 11 المقترحة (6 دفعات بالترتيب)

> المبدأ: **أولًا ما يفتح الوظيفة ويغلق الأمن (A)، ثم الترميم والصيانة (B/C)، ثم البنية (D/E)، وأخيرًا الرفاهية (F)**. كل دفعة على فرع `wip/11.x` + STOP GATE واختبار إنتاج قبل الدمج — نفس عُرف Wave 10.

### الدفعة 11.0 — `media-hls-proxy` (P0 — الوظيفة الأساسية)
- بناء **Proxy Endpoint** (وثيقة 04 §1): النسخة الأولى خيار **302 redirect** (أقل جهد، يعمل مع hls.js بلا تعديلات): `GET /api/v1/media/hls/{assetType}/{assetId}/{*path}` → استحقاق → تحقق المسار تحت HlsKey → 302 إلى presign لكل كائن.
- `GetPlaybackUrlQuery` عند Ready يعيد قاعدة الـ proxy (أو playlist URL عبر الـ proxy).
- **Rate limiting أولي** على النقطة (حد/طالب/دقيقة) — تُبنى معه لا بعده.
- اختبارات وحدة (مسار سليم/اجتياز/استحقاق/409-422 كما هي) + e2e بثّ حقيقي.
- **معيار النجاح**: تشغيل حلقة Ready من الطرف للطرف في المتصفح.

### الدفعة 11.1 — `security-hardening` (P0 الأمن + تنظيف)
- تدوير المفتاح (عملية Render — توثيقها في `docs/ops/`) + شدّ `AllowedOrigins` في `SetBucketCorsAsync` إلى أصول Vercel الفعلية بعد تأكيد البث.
- حذف كود Upstash الميت كليًا (الفئتان + اختباراتهما + catch المتحكم) وإزالة سجلات 10.13 المؤقتة (أو خفضها إلى Debug).
- تحديث `.env.example`/`docs/ops/*` وفقًا لذلك.

### الدفعة 11.2 — `content-recovery` (P0/P1 البيانات)
- أداة/endpoint إداري «إعادة ترميز» للحلقات القديمة (وضع `Pending` من `Failed`/`Ready`-قديم + إدراج الطابور) — مع حماية من التكرار.
- جرد أشجار HLS الموجودة في `CMSmedia` مقابل `HlsKey`s في القاعدة (سكربت SQL/list) → قائمة إعادة العمل.
- SQL إنقاذية موثّقة في `docs/ops/` (نمط `UPDATE course_episodes SET processing_status …`).

### الدفعة 11.3 — `upload-400-fix` + عمود `ProcessingError` (P1)
- ترقية سجلات مسار الرفع (جسم خطأ B2 عند فشل الـ PUT غير مرئي للـ API — أضف تقرير الواجهة عن آخر خطأ XHR في جسم `abort/complete`) ثم الإصلاح الجذري حسب التشخيص (قضية 04 §2).
- هجرة عمود `ProcessingStatusError` (نص) يُكتب عند الفشل من `VideoTranscodingService` (مقطع الرسالة التقنية) → الـ DTO يعرض الحقيقي بدل المُصنّع.

### الدفعة 11.4 — `ci-stability` (P2)
- Testcontainers (أو Postgres خدمة في GitHub Actions) لتشغيل `PostgresIntegration` فعليًا — توحيد العدد الكلي في CI بدل 440 فقط.
- سير عمل GitHub Actions: build + test + lint على كل PR/دفعة إلى wip/*.
- تقرير جودة دوري (عدد التحذيرات 17 ثابت — تقليصه تدريجيًا).

### الدفعة 11.5 — `player-polish` (P2/P3)
- مشغّل الصوت المخصص (تمريرًا بعقود Wave 10 نفسها: lease refresh + استئناف + علامات) أو ترقية المسار الموجز الحالي.
- ETA/نسبة للطالب أثناء المعالجة (يحتاج تقدمًا خادميًا — يُبنى على سجلات الطوار في عمود أو كاش Redis).
- manualChunks لـ CoursePlayerPage + حذف/توظيف `PlayerShell`.

> **تنبيه اعتمادية**: 11.0 تفتح الطريق لكل ما بعدها (البث أساس اختبار 11.2 وقياس 11.5). لا تبدأ 11.2 قبل استقرار 11.0 في الإنتاج. 11.1 و11.3 قابلتان للتوازي مع 11.0 إن توفرت جلسات متعددة.
