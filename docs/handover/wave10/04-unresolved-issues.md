## القضية 1 — HLS 401 Unauthorized (🔴 الحرجة — وظيفة الموجة الأساسية)

### العرَض ومتى يحدث
مشغّل الطالب لحلقة فيديو ذات `processingStatus=Ready` يعرض «تجديد الرابط…» إلى ما لا نهاية. تبويب الشبكة: طلب `master.m3u8` **ينجح أحيانًا أو يُجاب 401**، ثم طلبات المقاطع `index-*.m3u8`/`seg-*.ts` **كلها 401** من `s3.eu-central-003.backblazeb2.com`. (في مرحلة سابقة كان الحجب CSP — أُصلح في 10.12؛ الآن الرفض من الخادم ذاته.)

### السبب الجذري (المُستقر عليه)
**نموذج «رابط presigned واحد لكل كائن» لا يصلح لتقنية HLS متعددة الملفات**:
1. الـ API يوقّع `GET` لكائن واحد: `{key}/hls/master.m3u8` (سجل 10.13: `Presigned GET issued: … Key=…/master.m3u8`).
2. hls.js يجلب الـ master بنجاح، ثم **يحلّ الروابط النسبية** داخله (`index-360p.m3u8` → ثم `seg-0.ts`…) بجلبها **من نفس الأصل دون أي سلسلة استعلام توقيع**.
3. الدلو **خاص** ⇒ B2 يرد على كل مقطع غير موقّع بـ **401** (سلوك B2 المعروف: 401 للكائن المفقود/غير المصرّح في دلو خاص — لا 404).
4. المشغّل يعاملها كخطأ شبكة مؤقت ⇒ يُجدد رابط الـ master (الذي يظل صالحًا!) ⇒ **حلقة لا نهائية**: «تجديد الرابط…».

> **فرضية ثانوية موثّقة (من 10.13)**: كائنات شجرة HLS للحلقات المرمّزة على المزوّد القديم غير موجودة أصلًا في `CMSmedia` (لم تُهاجَر في 10.9) — أيضًا تُجاب 401. سطر `Presigned GET issued` + فحص الدلو يفرّق بين الحالتين فورًا: توقيع موجود لكن المقاطع غير موقّعة = القضية الجذرية أعلاه؛ الكائن نفسه غائب = فجوة بيانات.

### الحل المقترح — Proxy Endpoint (المخطط)
**الفكرة**: تمرير بث HLS كاملًا عبر الـ API بدل روابط مباشرة موقّعة — الـ API يوقّع (أو يجلب) كل كائن خادميًا:

```
[VideoPlayer/hls.js]  لا يعدّل مبدئيًا — config.xhrSetup أو loader مخصص
        │  كل طلب مقطع يذهب إلى الـ API نفسه:
        ▼
GET /api/v1/media/hls/{assetType}/{assetId}/{**path}     ← نقطة النهاية الجديدة
        │  (playback-url يُعيد هذه القاعدة بدل رابط B2 الموقّع)
        ▼
MediaHlsProxyHandler:
  1) بوابة الاستحقاق نفسها (X-Entitlement) + تحقق أن المسار يقع تحت HlsKey الأصل
     (منع اجتياز المسار: لا ../، الامتدادات m3u8/ts فقط)
  2) GetSignedUrlAsync(hlsKey-root/path) خادميًا ثم:
     - خيار أ (redirect 302): أعِد التوجيه للرابط الموقّع لكل كائن — بسيط،
       ويعمل مع hls.js بلا أي تعديل (يتبع الـ redirect)
     - خيار ب (streaming): بثّ الكائن عبر الـ API (Range-aware: أعد ترويسات
       Content-Range/Accept-Ranges/ETag) — تحكم كامل + سجل + بدون كشف البنية
  3) TTL/كاش: قوائم m3u8 لا تُكاش (قصيرة العمر)، مقاطع ts قابلة لكاش خاص قصير
```

**أمور تصميمية يجب حسمها**: (أ) خيار 302 مقابل البثّ — 302 أرخص على ذاكرة Render لكن يجعل المتصفح يرى روابط B2 الموقعة (مقبول: مؤقتة وقصيرة)؛ البثّ أخفي لكنه يستهلك带宽 الـ API ويستلزم تمرير Range بدقة. (ب) حد المعدل على النقطة (المقاطع كثيرة: كل 4 ثوان فيديو = مقطع). (ج) اختيار بديل هندسي أنظف طويل الأمد: توقيع الروابط داخل ملف m3u8 ذاته (requires معالجة القوائم — أكثر تعقيدًا).

### الملفات المطلوب تغييرها (تقدير أولي)
| الملف | التغيير |
|---|---|
| `apps/api/src/CMS.Application/Commands/Media/MediaCommands.cs` (+ DTOs) | استعلام/أمر جديد للـ proxy |
| `apps/api/src/CMS.Application/Handlers/Media/MediaHandlers.cs` | معالج البث (استحقاق + تحقق مسار + توقيع/تمرير Range) |
| `apps/api/src/CMS.Api/Controllers/MediaController.cs` | `GET /media/hls/{assetType}/{assetId}/{*path}` |
| `apps/api/src/CMS.Application/Handlers/Media/MediaHandlers.cs` (`GetPlaybackUrlQuery`) | عند Ready: أعِد قاعدة الـ proxy (أو ملف playlist مُعاد كتابته) بدل رابط B2 |
| `apps/student-web/src/features/media-player/video/VideoPlayer.tsx` | خيار أ: لا شيء (يتبع 302)؛ خيار ب: ضبط `xhrSetup`/loader |
| CSP (`apps/*/vercel.json`) | الخيار ب: لا نطاق B2 جديد لازم (نفس الأصل)؛ الخيار أ: يبقى `connect-src` كما هو |
| `docs/ops/*` + اختبارات | اختبارات وحدة للـ proxy (مسار سليم/اجتياز/استحقاق) + e2e |

### خطوات الاستنساخ
1. لوحة مشرف → ارفع فيديو قصيرًا → انتظر `Ready` (سجل: `Transcoding job completed … HlsKey=…`).
2. تسجيل دخول طالب مستحق → افتح صفحة الحلقة → تبويب الشبكة.
3. لاحظ: نجاح (أو 401) `master.m3u8` ثم 401 متكرر على `index-*.m3u8`/`seg-*.ts`، مع دوران «تجديد الرابط…».
4. في سجل Render: سطر `Presigned GET issued` يظهر للمفتاح `…/master.m3u8` فقط — ولا شيء للمقاطع (هذا هو الدليل).

### الإجراء الأول المقترح للجلسة القادمة
افتح رابط master الموقّع من السجل مباشرةً في متصفح (أو curl) → نزّل master.m3u8 → اقرأ مسارات المقاطع النسبية → جرب جلب مقطع واحد **بلا توقيع** (تأكيد 401) ثم **بسلسلة التوقيع المنقولة يدويًا** (تأكيد 200) — هذا يثبت التشخيص في دقيقتين ويمنح الأساس لمواصلة خيار 302 (الأسرع شحنًا).

## القضية 2 — Upload 400 Bad Request (🟠 عالية — غير مشخّصة بعد)

### متى رُصد
حالة رفض رفع أُبصرت في اختبار الإنتاج بعد نشر مسار B2 (رفع من لوحة المشرف يُجاب **400** عند initiate أو عند الـ PUT المباشر إلى B2 — **UNVERIFIED: الرصد السابق للمهمة لم يُلحق سجلات Render المحددة؛ هذه القضية تحتاج أول تفقّد**).

### السجلات الملتقطة / المتاحة
- سجل 10.13 `Presigned GET issued` لا يغطي الرفع (يغطي GET فقط) — لكن مسار الرفع يملك ما يكفي إذا فُعّل التفقّد:
  - `Single-PUT presign: whole-file UploadUrl for episode …` (عند initiate الناجح — وجوده ينفي كون 400 من الـ API ويحوّل التهمة إلى B2/المتصفح).
  - خريطة 503/400 للمشكلة التخزينية (منذ 10.8c) في `ExceptionHandlingMiddleware`.
  - سجلات `S3 multipart initiate rejected` (10.8d) — تركت للصف القديم.
- **لا سجل مخصص لفشل الـ PUT من المتصفح إلى B2** (الرفع لا يمر بالـ API) — يُقرأ من تبويب الشبكة في المتصفح مباشرة.

### الأسباب المحتملة (مرتبة بالأرجحية)
1. **انعدم تطابق التوقيع عند B2 للـ PUT**: رابط 10.8f يوقّع `Content-Type` + `Content-Length` — أي انحراف (متصفح يضيف encoding، حجم 0 لملف فارغ، أو شمّ نوع خاطئ للملفات ذات الأسماء العربية `file.type=''`) يرد B2 بـ **400/403 SignatureDoesNotMatch**.
2. **انتهاء صلاحية الرابط (600s)** لملف كبير على اتصال بطيء → 403 (يظهر للواجهة كفشل عام).
3. **قيد B2 غير المكتوب**: حدود Content-Length أو نوع المحتوى عند التوقيع presign على S3-gateway لـ B2.
4. 400 من الـ API نفسه عند `complete-upload` (اختبار HEAD يُرجع `BLOB_NOT_FOUND` ← 400 مقصود إذا لم يصل الكائن — أي أن الـ PUT فشل صامتًا قبله).

### خطوات التنقيح التالية
1. جرّب رفعًا في الإنتاج مع فتح تبويب الشبكة: **أي طلب بالضبط** يرد 400 (initiate أم PUT إلى B2 أم complete)؟ ونص جسم الخطأ (B2 يُرجع XML `<Error><Code>…</Code>` — الكود حاسم).
2. قارن ترويسات الـ PUT المرسلة مع ما وُقّع (النوع والحجم حرفيًا).
3. أعد بملف لاتيني الاسم صغير (<10MB) ثم بمحتوى عربي الاسم — عزل فرضية الشمّ.
4. إن كان الـ 400 من B2 بـ `SignatureDoesNotMatch`: تحقق من سلوك المتصفح مع `Content-Type` الفارغ (10.8f يعالجه بالشمّ — لكن تحقق أنه يعمل على B2 كما عمل على R2).

### الإجراء الأول المقترح
**جرّب رفعًا واحدًا مع تبويب الشبكة مفتوحًا واقرأ جسم الـ 400 من B2** — سطر واحد يرتب الفرضيات كلها. ثم قرّر: إصلاح توقيع (نوع/حجم) أم حد مزوّد.

## القضية 3 — خطوط Google و CSP (🟡 مُصلَّحة كوديًا — بانتظار التأكيد)

- **الحالة**: أُصلحت في 10.13 (`17754a1`، مُنشَرة إلى main ⇒ Vercel أعاد النشر): `style-src` += `https://fonts.googleapis.com` في التطبيقين (`apps/*/vercel.json`) — التوجيه الصحيح لأن الاستيراد ورقة أنماط في `globals.css`؛ `font-src` كان يشمل `fonts.gstatic.com` من قبل.
- **المتبقي**: تأكيد حي واحد بعد النشر — افتح أي صفحة وافحص: لا طلبات خطوط محجوبة في console، والخطوط IBM Plex Sans Arabic/DM Mono تُحمّل. **إن بقيت محجوبة**: التحقق من أن Vercel أعاد النشر فعلاً بعد الدفعة (ترويسات `vercel.json` تُطبَّق لكل deployment) وأن CSP في تبويب الشبكة يحمل القيمة الجديدة.
- **الإجراء الأول**: فحص DevTools → Network → فلتر `fonts.` — نجاح = إغلاق القضية.

## القضية 4 — المفتاح الرئيسي ما زال في Render (🟠 أمنية)

### الخطر
`Storage__S3__AccessKey/SecretKey` الحالية في Render هي (حسب معرفة الجلسة) **مفتاح التطبيق الرئيسي (Master application key) لحساب B2**: يملك صلاحيات كاملة على **كل** الدلاء وكل العمليات (حتى إنشاء مفاتيح ودلاء). أي تسريب له (سجلات، تسريب بيئة، خطأ نشر) = استيلاء كامل على حساب التخزين. كما أن استخدامه يُعطّل مبدأ أقل-صلاحية ويُصعّب التدقيق.

### خطوات المعالجة (التدوير إلى مفتاح scoped)
1. (تم جزئيًا) المشرف أنشأ **`cms-api-key-01`** (Read & Write) — تأكد من نطاقه: الدلو `CMSmedia` حصرًا، والصلاحيات: `readBucket`, `writeBucket` (يشمل listBuckets لنطاقه), `setBucketCors` (يلزم لعمل 10.10 التلقائي!), `readFiles`, `writeFiles`, `deleteFiles` — **دون** `listAllBuckets`/`writeKeys`/إدارة حساب.
2. في لوحة Render → Environment → عدّل `Storage__S3__AccessKey` = keyID الجديد و`Storage__S3__SecretKey` = applicationKey الجديد → حفظ ⇒ إعادة نشر تلقائية.
3. **صفر تغيير كود** (الكود config-driven حصرًا — تحقّق: `rg` لا يجد أي مفتاح حرفي في الكود).
4. تحقق بعد الإقلاع: سجل 10.10 `B2/S3 CORS configuration applied successfully to bucket CMSmedia.` موجود (يثبت أن المفتاح يملك `setBucketCors`)؛ ثم سجل 10.13 `Presigned GET issued` — **keyID الجديد مرئي في `X-Amz-Credential`** ← دليل التدوير.
5. **أبطل المفتاح الرئيسي** (أو احذفه) من لوحة B2 بعد سيران كل شيء ≥24 ساعة.
6. (لاحقًا) أتمتة تدوير دوري + وضع الأسرار في Secret Store بدل متغيرات بيئة صريحة — بند دَين في الوثيقة 05.

### الإجراء الأول المقترح
خطوة 2 أعلاه (تحديث القيمتين في Render) — أقل من دقيقتين وتستحق أن تكون أول فعل أمني في الجلسة القادمة.
