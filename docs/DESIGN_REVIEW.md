## 3. Visual Hierarchy

### 3.1 معايير التقييم

- هل العناصر الأهم بصرياً هي الأهم وظيفياً؟
- هل التسلسل الهرمي واضح (H1 > H2 > H3 > body)?
- هل الأحجام والأوزان تعكس الأهمية؟
- هل المساحات البيضاء توجّه الانتباه؟

### 3.2 التقييم

#### ✅ نقاط القوة

1. **هرم طباعي واضح**:
   - Display (64px) → H1 (48px) → H2 (36px) → H3 (28px) → H4 (22px) → Body (16px).
   - الفروق واضحة وتعكس الأهمية.

2. **استخدام الوزن (weight) بذكاء**:
   - العناوين: 700-800 (Bold/ExtraBold).
   - النص الأساسي: 400 (Regular).
   - التأكيد: 500-600 (Medium/SemiBold).
   - Captions: 400 (Regular).

3. **الألوان توجّه الانتباه**:
   - Primary 700 (#1976D2) للأزرار الرئيسية فقط (1-2 في الصفحة).
   - Success/Danger/Warning للأحداث الدلالية فقط.
   - Neutral للنصوص الأساسية.

4. **المساحات البيضاء فعّالة**:
   - Padding كافٍ للبطاقات (20-32px).
   - Gap بين العناصر (12-16px).
   - مساحات كبيرة بين الأقسام (32-48px).

5. **بطاقة "متابعة الدراسة" متميّزة**:
   - خلفية gradient primary تجذب الانتباه.
   - تظهر أولاً بعد الإحصائيات.
   - زر CTA واضح (أبيض على أزرق).

6. **Stat Cards متوازنة**:
   - 4 بطاقات بنفس الحجم.
   - أيقونة + قيمة + label + trend في ترتيب منطقي.
   - الأرقام (28px) أكبر من الـ labels (13px).

#### ⚠️ ملاحظات

- في Dashboard، الـ Hero يحتل مساحة كبيرة نسبياً — قد يحتاج تخفيض على Mobile.
- في Question Card، الـ explanation panel قد يطول — يُفضّل collapsible.

### 3.3 الدرجة: 9.5/10 ✅

## 4. Accessibility (WCAG 2.1 AA)

### 4.1 معايير التقييم

- WCAG 2.1 Level AA compliance.
- دعم لوحة المفاتيح الكامل.
- دعم قارئ الشاشة.
- ARIA labels صحيحة.
- Semantic HTML.

### 4.2 التقييم

#### ✅ نقاط القوة

1. **التزام رسمي بـ WCAG 2.1 AA**:
   - 13 إرشاد موثّق في `docs/ACCESSIBILITY.md`.
   - مبادئ POUR الأربعة مغطّاة.
   - قائمة فحص شاملة قبل كل مكوّن.

2. **Semantic HTML في النماذج**:
   - `<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, `<aside>`, `<footer>`.
   - `<h1>` مرة واحدة في الصفحة.
   - هرم العناوين صحيح (h1 → h2 → h3).

3. **دعم لوحة المفاتيح**:
   - كل الإجراءات قابلة للوصول بالكيبورد.
   - ترتيب التركيز منطقي.
   - Focus ring مرئي (`box-shadow: 0 0 0 4px rgba(...)`).
   - Skip links مخطّطة.

4. **ARIA usage صحيح**:
   - `aria-label` للأيقونات بلا نص.
   - `aria-describedby` للحقول مع hints.
   - `aria-live` للإشعارات الديناميكية.
   - `aria-current="page"` للعنصر النشط.
   - `aria-busy` للأزرار في حالة loading.

5. **دعم RTL كامل**:
   - `dir="rtl"` في `<html>`.
   - استخدام logical properties (`ps-*`, `pe-*`, `ms-*`, `me-*`).
   - الأيقونات الاتجاهية تتبدّل تلقائياً.

6. **Reduced motion**:
   - احترام `prefers-reduced-motion`.
   - Framer Motion مع `reducedMotion="user"`.

7. **Touch targets**:
   - ≥ 44x44px على Mobile.
   - أزرار Mobile: 48-52px ارتفاع.

#### ⚠️ ملاحظات

1. **نقص في `lang` attribute على الأجزاء الإنجليزية**:
   - بعض المصطلحات الإنجليزية (مثل "Ctrl K") تحتاج `<span lang="en">`.

2. **صور placeholder بلا `alt`**:
   - في النماذج، الصور placeholders تحتاج `alt=""` أو وصف.

3. **Live regions للـ Toasts**:
   - التأكد من إضافة `aria-live="polite"` على حاوية الـ toasts.

### 4.3 الدرجة: 9.0/10 ✅

### 4.4 إجراءات تصحيحية مطلوبة

| # | الإجراء | الأولوية |
|---|--------|---------|
| A-1 | إضافة `lang="en"` على المصطلحات الإنجليزية | متوسطة |
| A-2 | إضافة `alt` للصور (حتى placeholders) | عالية |
| A-3 | التأكد من `aria-live` على حاوية الـ toasts | عالية |

   - تباين منخفض (2.8:1 و 3.1:1).

   - الـ 500 يُسمح فقط للخلفيات + نص أبيض، أو للأيقونات الكبيرة.

## 6. Typography

### 6.1 معايير التقييم

- هل الخطوط مناسبة للمحتوى الطبي؟
- هل الهرم الطباعي متّسق؟
- هل الأحجام متجاوبة؟
- هل دعم العربية كافٍ؟

### 6.2 التقييم

#### ✅ نقاط القوة

1. **اختيار خط Cairo ممتاز**:
   - حديث (2018)، يدعم 9 أوزان.
   - واضح على الشاشات الصغيرة.
   - مجاني من Google Fonts.
   - يدعم الأرقام العربية والإنجليزية.
   - يدعم RTL.

2. **خط Inter للإنجليزية**:
   - صمّم خصيصاً للشاشات.
   - واضح حتى 11px.
   - متغير (variable font) — أداء أفضل.

3. **JetBrains Mono للكود**:
   - يفرّق بوضوح بين 0/O، 1/l/I.
   - علامات الترقيم واضحة.

4. **هرم طباعي متّسق**:
   - 10 مستويات (Display → Overline).
   - نسبة 1.250 (Major Third) متناسقة.
   - Line-height مناسب (1.1-1.6).

5. **أحجام متجاوبة**:
   - Mobile / Tablet / Desktop / Large.
   - تكبير تدريجي حسب الشاشة.

6. **Antialiasing مفعّل**:
   - `-webkit-font-smoothing: antialiased`.
   - `-moz-osx-font-smoothing: grayscale`.
   - `text-rendering: optimizeLegibility`.

7. **قواعد ذكية**:
   - `text-align: start` (لا `justify` للعربية).
   - `max-width: 65ch` للنصوص الطويلة.
   - `tabular-nums` للإحصائيات.

#### ⚠️ ملاحظات

1. **تحميل الخطوط**:
   - `display=swap` مفعّل — جيد.
   - لكن لا `preload` للخطوط الحرجة.
   - **الحل**: إضافة `<link rel="preload">` لـ Cairo 400 + 700.

2. **Fallback fonts**:
   - الـ fallback stack جيد (`Tajawal`, `Noto Sans Arabic`, `system-ui`).
   - لكن قد يحدث FOUT (Flash of Unstyled Text) على الإنترنت البطيء.

3. **Letter spacing**:
   - للعربية: 0 (افتراضي) — صحيح.
   - للإنجليزية: -0.01em للعناوين، 0 للنص — صحيح.
   - للأرقام: `tabular-nums` — صحيح.

### 6.3 الدرجة: 9.0/10 ✅

## 7. Spacing

### 7.1 معايير التقييم

- هل النظام متناسق (4px baseline)?
- هل المسافات تعكس العلاقات؟
- هل المساحات البيضاء كافية؟

### 7.2 التقييم

#### ✅ نقاط القوة

1. **نظام 4px baseline صارم**:
   - كل المسافات مضاعفات لـ 4px.
   - 17 مستوى (0 → 128px).
   - لا قيم عشوائية.

2. **نظام Token كامل**:
   - `--s-0` إلى `--s-32`.
   - متغيّرات CSS قابلة لإعادة الاستخدام.

3. **استخدام منطقي**:
   - Page padding: 16px (mobile) / 32px (desktop).
   - Card padding: 20-32px.
   - Card gap: 16px.
   - Section gap: 32-48px.
   - Form field gap: 20px.
   - Button padding: 10px 20px.

4. **المساحات البيضاء فعّالة**:
   - لا ازدحام.
   - تنفصل بين الأقسام بوضوح.
   - تعطي راحة بصرية.

5. **Grid system متّسق**:
   - 12-column على Desktop.
   - Gap: 16-24px.
   - Container max-width: 1280px.

#### ⚠️ ملاحظات

1. **بعض المسافات في النماذج غير موحّدة**:
   - مثلاً: `padding: 28px 32px` في Hero vs `padding: 20px` في StatCard.
   - **الحل**: توحيد قيم الـ padding للبطاقات المتشابهة.

2. **Mobile spacing**:
   - تقليل الـ padding على Mobile صحيح.
   - لكن بعض البطاقات قد تحتاج تقليل أكبر (مثلاً: 16px بدل 20px).

2. **أحجام الأيقونات**:
   - في النماذج، بعض الأيقونات 18px، أخرى 20px في نفس السياق.
   - **الحل**: توحيد أحجام الأيقونات حسب السياق (16/20/24/32).

3. **Shadow levels**:
   - استخدام shadow-md و shadow-lg و shadow-glass بشكل متبادل أحياناً.
   - **الحل**: توثيق متى يُستخدم كل مستوى.

## 9. Responsiveness

### 9.1 معايير التقييم

- هل يعمل على Mobile (360px)?
- هل يعمل على Tablet (768px)?
- هل يعمل على Desktop (1024px+)?
- هل الـ breakpoints منطقية؟
- هل الـ touch targets كافية؟

### 9.2 التقييم

#### ✅ نقاط القوة

1. **Mobile-First Approach**:

## 11. Originality

- هل يبدو مولّداً بواسطة AI؟

### 11.2 التقييم

1. **ليس قالباً جاهزاً**:
   - لا استخدام لـ Bootstrap templates.
   - لا نسخ مباشر من Tailwind UI.

   - "أحسنت! +1 نقطة" بدل "الإجابة صحيحة".
   - نبرة دافئة لكن احترافية.

7. **اختيار Radix UI + TanStack Table**:
   - ليس مجرد "Bootstrap" أو "Material UI".
   - مكوّنات headless قابلة للتخصيص الكامل.

#### ⚠️ ملاحظات

1. **Glassmorphism قد يبدو شائعاً**:
   - Glassmorphism أصبح شائعاً جداً (2020+).
   - لكن تطبيقنا محسّن (شفافية معتدلة، backdrop-filter مدروس).

الانتقال إلى **Phase 12: Design Approval** للحصول على:

1. الاعتماد الرسمي من العميل.
2. تسجيل حالة "Approved" في `PROJECT_STATUS.md`.
3. فتح مرحلة التطوير البرمجي (Phase 13+).
