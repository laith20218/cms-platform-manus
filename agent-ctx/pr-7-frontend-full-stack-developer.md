## Deviations from the constraints (deliberate, minimal, documented)

1. **`App.tsx` touched beyond dictionary keys** (PR-6-modified file). Three additive wirings were structurally REQUIRED by the task's own features and none reverts PR-6: `token` prop to AdminsCenter (the effective-access drawer cannot fetch without it), the inline `RoleDeleteConflictBanner` inside App's existing role-delete ConfirmDialog (task C demands the banner "in the confirm dialog", and that dialog lives in App), and converting the 7 admin/role lifecycle catch blocks to `apiErrorHumanMessage` (task B demands verifying — and enabling — bilingual surfacing of the new codes). Nothing else in App.tsx changed.
2. **`lib/api.ts` touched** (PR-6-modified file) — but only by APPENDING the PR-7 typed helpers at the file end, exactly the additive pattern the task's READ FIRST brief describes ("how to add typed helpers"); no PR-6 line altered.
3. **`GET /api/v1/admin/settings/{key}/history` is NOT in the current backend tree** (searched all controllers; only the write-side history rows exist). The drawer implements the task's documented contract exactly (PagedResult of id/key/oldValue/newValue/changedBy/changedByName/changedAt/reason) with honest loading/empty/error states; against today's API it will surface the error state rather than fabricate data. Zero `apps/api` changes were made by me.
4. Role-delete confirm stays owned by App (existing ConfirmDialog) rather than being re-homed into RolesCenter — moving it would have meant a larger App.tsx edit than the two-line banner wiring; the conflict copy/logic itself lives + is tested in RolesCenter.tsx.
5. New interactive affordances (history-open, effective-access, bool segmented) use ≥44px targets per the accessibility constraint; pre-existing row icon buttons were left at the repo's established sizing (out of PR-7 scope).
